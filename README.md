# Модератор 2.5

Telegram-бот модерации с единой панелью в ЛС, обжалованиями, объяснениями ИИ, карточками участников, историей решений и оформлением только для владельца.

## Русский интерфейс

Переведены режимы, категории нарушений, решения, обжалования, состояние участника, действия в журнале, рекомендации, настройки оформления, уведомления и собственные сообщения об ошибках. Контекст переписки показывается читаемым текстом. Даты отображаются в формате ДД.ММ.ГГГГ ЧЧ:ММ с пометкой «мск»; хранение времени в базе не меняется.

В базе и протоколах сохранены прежние технические коды для совместимости. Команды, названия файлов, переменные окружения, поля ответа ИИ, названия внешних моделей и имена сервисов сохраняют техническое написание. Пользовательские имена, исходные сообщения, цитаты и собственные шаблоны владельца автоматически не переводятся. Встроенные исходные шаблоны обновлены под прежними идентификаторами.

## Компактная структура

В комплекте 7 файлов:

| Файл | Назначение |
| --- | --- |
| bot.py | Запуск, подключение SQLite, команды, панель и обжалования |
| moderation.py | Миграции, журнал, ИИ, режимы работы и применение санкций |
| interface.py | Оформление, встроенный каталог, премиум-эмодзи и синхронизация чатов |
| language_filter.py | Локальный контекстный фильтр, транслит и литспик |
| test_bot.py | Все 72 офлайн-теста |
| requirements.txt | Зависимости |
| README.md | Эта инструкция |

Шаблоны включены в interface.py; отдельный JSON больше не нужен. Их ID и таблицы SQLite сохранены, поэтому прежнее оформление, настройки, предупреждения, история и обжалования совместимы. Модерация регистрируется напрямую, без подмены обработчика-заглушки. Оформление читается из кеша; сохранение и сброс сразу обновляют кеш и базу. Повторное сохранение неизменных имён чатов/участников не переписывает строки. Очистка исходных текстов использует индекс срока хранения и не обновляет уже пустые записи.

## Установка и обновление на Bothost

1. Остановите процесс. Сделайте резервную копию файла SQLite, указанного в DB_PATH; при штатной остановке не оставляйте другой работающий процесс бота. Либо используйте SQLite backup для живой базы.
2. Замените код семью файлами из этого архива. Сохраните сам файл базы, секреты и переменные окружения, особенно BOT_TOKEN, BOT_OWNER_ID и DB_PATH.
3. При обновлении поверх версий 2.0–2.3 старые модули больше не нужны. Удаляйте только эти устаревшие файлы: ai_analyzer.py, moderation_store.py, moderator2.py, ui_theme.py, ui_owner.py, chat_sync.py, custom_emoji.py, ui_catalog.json; прежние отдельные test_*.py, кроме заменяемого test_bot.py; README.txt, UPDATE_2_0.md, CUSTOMIZATION.md, FIX_2_2.md, PREMIUM_EMOJI.md. Базу и файлы с секретами не удаляйте.
4. Установите зависимости: `pip install -r requirements.txt`. Требуется Python 3.10+.
5. Команда запуска осталась прежней: `python bot.py`. Миграции выполняются автоматически. Указывайте DB_PATH на постоянном хранилище хостинга.
6. Откройте `/start` в ЛС. Для проверки прав боту нужны права администратора группы; для санкций — удалять сообщения, ограничивать и блокировать участников.

Вручную объединять базы или переносить значения оформления не нужно. При откате остановите бота и восстановите резервные копии прежних файлов и базы. Не запускайте тесты одновременно с боевым процессом в том же интерпретаторе: тестовый файл принудительно использует фиктивный токен и базу в памяти.

## Переменные окружения

| Переменная | Значение |
| --- | --- |
| BOT_TOKEN | Обязательный токен бота |
| DB_PATH | Путь к базе; по умолчанию moderation.sqlite3 |
| BOT_OWNER_ID | Положительный числовой Telegram ID владельца редактора |
| WARNING_LIMIT | Лимит предупреждений по умолчанию: 3 |
| MUTE_MINUTES | Мут по умолчанию: 15 минут |
| RESET_AFTER_DAYS | Сброс активного счётчика после 7 дней без нарушений |
| TEXT_RETENTION_DAYS | Хранение исходного текста и контекста: 30 дней, минимум 1 |
| AI_CHAT_COMPLETIONS_URL | Полный HTTPS URL chat completions провайдера |
| AI_API_KEY | Ключ провайдера ИИ |
| AI_MODEL | Модель с поддержкой messages и JSON response_format |
| CUSTOM_EMOJI_ENABLED | По умолчанию 1; значение 0 отключает специальные эмодзи при отправке |

Настройки лимита, длительности мута и режима, сохранённые для конкретного чата в панели, имеют приоритет над значениями по умолчанию.

## Панель и подключение чатов

`/start`, `/panel`, `/admin` открывают видимую панель в конце переписки. Далее бот редактирует это сообщение. Старые панели остаются в истории, входящие сообщения в ЛС не удаляются.

Бот запоминает чаты из входящих событий, даже если сообщение не дошло до модерации. «Синхронизировать чаты» и `/sync` восстанавливают известные ID из сохранённых таблиц, обновляют названия и обнаруживают доступную связанную группу обсуждений. Telegram Bot API не предоставляет полный перечень всех ранее подключённых чатов: неизвестный базе чат нужно один раз выбрать через «Найти существующий чат». Выбор открывает временную клавиатуру Telegram, затем права пользователя и бота проверяются заново.

Альтернативы: `/connect -100...` в ЛС или `/panel@имя_бота` в нужной группе. Канал и его обсуждения — разные чаты; для модерации комментариев боту нужны права в группе обсуждений. Если после переустановки пропали и настройки, и история, проверьте DB_PATH и восстановите сохранённую базу.

## Режимы модерации

- Наблюдение: анализ и очередь проверки без удаления сообщений и наказаний. Оценки администратора влияют только на статистику.
- Подтверждение: подозрительное сообщение остаётся в очереди. После подтверждения открывается отдельный экран санкции; при применении сообщение удаляется по возможности.
- Автоматически: однозначные локальные нарушения и рекомендации ИИ предупредить или ограничить отправку сообщений с оценкой не ниже 0.95 и точной цитатой приводят к санкции. Спорные случаи с рекомендацией проверить вручную или наблюдать остаются на проверке. Автобанов нет.

Для чатов без сохранённого режима по умолчанию включено наблюдение. Настройки режима из прежней версии сохраняются. Выключение фильтра останавливает анализ. После лимита предупреждений применяется мут; рекомендация ограничить отправку означает мут. Администраторы, боты и сообщения от имени канала не модерируются. Мут доступен в супергруппах.

Подтверждение атомарно резервирует решение; два администратора не применят его дважды. Ручные подтверждения одноразовые. При неоднозначном сетевом результате или перезапуске во время санкции запись получает статус «Нужно проверить результат»: проверьте действующий статус в Telegram и выполните необходимое действие из карточки; автоматического повтора нет.

Карточки содержат текущие предупреждения, статистику санкций с момента внедрения журнала, состояние Telegram, историю решений, последние действия и обжалования. Дату первого появления старых участников и прежние санкции нельзя восстановить из одних старых счётчиков. История обжалований хранится в appeals, действия — в audit_log. Обжалования доступны в ЛС и относятся к мутам.

## ИИ и хранение текста

ИИ необязателен: без всех трёх AI-переменных работает локальный фильтр; при ошибке ИИ тоже используется локальный результат в пределах выбранного режима. В наблюдении сбой ИИ не включает санкции.

Провайдеру передаются сообщение, до шести предыдущих сообщений за последние десять минут (до 800 символов каждое), текст сообщения, на которое ответили, и счётчик предупреждений. Перед подключением проверьте допустимость такой передачи для своего чата и условия провайдера. На один HTTP-запрос отведено 12 секунд; одновременно выполняются до четырёх запросов, при высокой нагрузке образуется очередь.

Ответ ИИ: category, confidence, reason, evidence, action. Процент — субъективная оценка модели, а не доказанная вероятность. Некорректный ответ, выдуманная цитата, ошибка HTTP или таймаут возвращают локальный результат. Локальному правилу не приписывается процент уверенности.

По сроку хранения очищаются исходный текст, цитата и контекст. Категория, объяснение, версия модели и правил, результаты проверки остаются. Очистка выполняется при анализе, просмотре истории и фоново раз в час. Тексты прошедших проверку сообщений не хранятся в базе; ограниченный контекст находится в памяти. Копии базы и данные у ИИ-провайдера имеют собственные сроки хранения.

## Оформление только владельцу

Отправьте `/id` боту, добавьте свой числовой ID в BOT_OWNER_ID на хостинге и перезапустите процесс. Затем откройте `/design` или «🎨 Оформление». Отсутствующий или некорректный BOT_OWNER_ID закрывает редактор для всех. Первому посетителю права владельца не выдаются; обычные администраторы не получают доступ.

Можно менять тексты, заголовки, подписи и эмодзи, общий стиль кнопок и отдельной подписи, количество кнопок в ряду. Есть поиск по текущему/исходному тексту, предпросмотр, сохранение и сброс. Одинаковые подписи используют общий элемент каталога. Изменения глобальны для всех пользователей и видны при следующем открытии экрана; прежние сообщения в группах не редактируются задним числом.

Сохраняйте поля `{v0}`, `{v1}` и их количество повторений. Предпросмотр подставляет 123 вместо данных. Для текстов доступны поддерживаемые HTML-теги Telegram; в составных экранах фрагменты показываются отдельно, сохраняйте их граничные теги. Команды `/design`, `/id` и элементы самого редактора остаются фиксированными для восстановления доступа. Права и назначения кнопок не меняются через оформление. Имя и аватар бота меняются отдельно в BotFather; шрифт, фон и анимация определяются клиентом Telegram.

## Премиум-эмодзи

При изменении текста отправляйте премиум-эмодзи прямо из Telegram: ID извлекаются из сущностей сообщения автоматически. В тексте можно использовать несколько; на кнопке — одну иконку в начале и название после неё. Также поддерживается `<tg-emoji emoji-id="5368324170671202286">👍</tg-emoji>` с обычной Unicode-альтернативой внутри.

По правилам Telegram Bot API специальные эмодзи доступны ботам с дополнительными именами Fragment либо в напрямую отправленных сообщениях в ЛС, группы и супергруппы при Premium у настоящего владельца бота в BotFather. BOT_OWNER_ID сам по себе этих прав не даёт. Официальная справка: https://core.telegram.org/bots/api#formatting-options .

При явном отказе Telegram, связанном со специальным эмодзи, запрос повторяется один раз с обычной альтернативой. Конфигурация сохраняется. Сетевые таймауты и посторонние ошибки не вызывают такой повтор. Для принудительного отключения используйте CUSTOM_EMOJI_ENABLED=0 и перезапуск. На старых клиентах и в уведомлениях Telegram может показывать обычный эмодзи.

## Проверка

`python -m unittest discover -v`

72 офлайн-теста охватывают прежние функции, фильтр, права, режимы, обжалования, синхронизацию, премиум-эмодзи, миграции и оптимизации. Проверено отсутствие SQL-запросов при повторном чтении кеша оформления, отсутствие перезаписи одинаковых метаданных и уже очищенного текста. Проверка с настоящим Bot API, провайдером ИИ и Bothost не проводилась.
