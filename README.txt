Telegram Moderator — панель и обжалования в личных сообщениях

ОБНОВЛЕНИЕ НА BOTHOST
1. Останови старый процесс бота. Сохрани резервную копию moderation.sqlite3
   (или файла по DB_PATH). При работающем боте SQLite может использовать
   дополнительные файлы -wal и -shm, поэтому копируй базу после остановки.
2. Замени bot.py и requirements.txt файлами из этого архива.
   Старую базу данных не удаляй: таблицы панели добавятся автоматически.
3. Сохрани прежний BOT_TOKEN. Установка: pip install -r requirements.txt
   Команда запуска: python bot.py
4. Запусти бот. Каждый администратор должен открыть ЛС бота и нажать «Старт».
5. В ЛС отправь /panel. Если чат не появился, отправь /panel в группе
   или в ЛС бота /connect -1001234567890 с настоящим ID нужного чата.
   Бот проверит, что ты и он — администраторы.

ПАНЕЛЬ В ЛС
/start, /panel или /admin — список чатов, где пользователь администратор.
Для каждого чата отдельно доступны:
- включение и выключение автоматического фильтра;
- лимит предупреждений (1–100), длительность мута (1–10080 минут);
- просмотр участников с действующими предупреждениями (последние 30);
- поиск участника по ID или известному боту @username;
- мут, снятие мута со сбросом предупреждений, отдельный сброс предупреждений;
- очередь обжалований (по 10, после обработки открой её снова).
/cancel — отмена текущего ввода в ЛС.
Права администратора проверяются заново при каждом действии.
Настройки, черновики, счётчики и заявки сохраняются в SQLite.

ОБЖАЛОВАНИЯ
Под сообщением о муте есть ссылка «Обжаловать в ЛС».
Она открывает бота, где участник нажимает «Старт» и пишет причину.
Причина и кнопки решения отправляются только в ЛС создателю и
администраторам чата; в общий чат они не публикуются.
Для прямой доставки администратор должен заранее запустить бота в ЛС
и не блокировать его. Если доставка недоступна, заявка остаётся в панели.
Одна активная заявка на участника в каждом чате. При выборе обжалования
в другом чате текущий черновик заменяется. /cancel отменяет черновик,
но не уже отправленную заявку.
Принятие снимает мут и сбрасывает предупреждения. Отклонение оставляет
ограничение до окончания его срока. Решение отправляется участнику в ЛС.
Если снять мут не удалось, заявку можно обработать повторно.
Старые кнопки решений от прошлой версии не действуют: нужно подать новую
заявку через ЛС. Старые кнопки начала обжалования открывают ЛС бота.

ГРУППОВЫЕ КОМАНДЫ
/rules, /warns — правила и свой счётчик.
/mute или /mute 45 — ответом на сообщение участника, только для админов.
/unmute — ответом на сообщение; также /unmute @username или /unmute ID.
/panel — ссылка на панель в ЛС. Сама панель не выводится в группу.

КАНАЛЫ И ГРУППЫ
Модерация сообщений участников и муты работают в супергруппе обсуждений
канала. Для самого канала Telegram не предоставляет мут подписчика
через restrictChatMember. Подключай именно группу комментариев.
Бот должен быть администратором с правами удаления сообщений и
ограничения участников. Сообщения администраторов и сообщения от имени
канала/группы не фильтруются. Личные сообщения не модерируются.

ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ
BOT_TOKEN         обязательный токен; в архиве токенов нет
DB_PATH           путь к SQLite, по умолчанию moderation.sqlite3
WARNING_LIMIT     начальный лимит предупреждений, по умолчанию 3
MUTE_MINUTES      начальная длительность мута, по умолчанию 15
RESET_AFTER_DAYS  сброс после указанного числа дней без нарушений, по умолчанию 7
Сохраняй SQLite в постоянном хранилище хостинга, чтобы перезапуски и
обновления не стирали настройки. Настройки из панели имеют приоритет
над начальными WARNING_LIMIT/MUTE_MINUTES для конкретного чата.
Рекомендуется Python 3.11/3.12.

ПРОВЕРКА
python -m unittest -v
Тесты используют временную базу в памяти и имитацию Telegram API,
не подключаются к рабочему боту. Фильтр слов оставлен из исходной версии:
он эвристический и может ошибаться. После обновления проверь выдачу
и снятие мута на тестовом участнике в отдельной супергруппе.
