# Moderator 2.1

Дополнение: настройка оформления доступна только владельцу через BOT_OWNER_ID. Полная инструкция — CUSTOMIZATION.md. Остальные функции 2.0 сохранены.

## Обновление на Bothost

1. Остановите бота. Сохраните копию существующего файла SQLite (по DB_PATH), прежде чем заменять код. Для WAL-базы копируйте после штатной остановки либо через SQLite backup.
2. Замените файлы проекта содержимым архива. Оставьте прежние BOT_TOKEN, DB_PATH и саму базу. Для DB_PATH используйте постоянное хранилище хостинга.
3. Установите requirements.txt. Команда запуска: python bot.py (Python 3.10+).
4. Откройте /panel в ЛС, выберите чат → «ИИ · Режим работы».

Старые настройки, счётчики, пользователи и обжалования сохраняются. Миграция добавляет таблицы автоматически. Историческую дату первого появления старых участников и старые санкции восстановить из прежних счётчиков невозможно: карточка прямо это отмечает. Откат к старому коду: остановить бота и восстановить резервную копию базы и прежние файлы.

**После обновления каждый чат по умолчанию работает в наблюдении.** Сообщения не удаляются, предупреждения и муты не выдаются. Чтобы вернуть автоматические санкции локального фильтра, включите «Автоматически» и подтвердите изменение. Выключенный фильтр полностью останавливает анализ.

## Три режима

- Наблюдение: сбор решений; «Подтвердить» и «Отклонить» только оценивают решение, санкций нет.
- Подтверждение: подозрительные сообщения остаются в очереди. Подтверждение открывает дополнительный экран санкции. Предупреждение либо мут по прежнему лимиту; рекомендация mute означает мут. Одобренное сообщение удаляется по возможности.
- Автоматически: локальные нарушения и рекомендации ИИ warn/mute с оценкой не ниже 0.95 и цитатой приводят к санкции; review/observe остаются на проверке. Автобанов нет. Модельная оценка не является измеренной вероятностью.

Локальный фильтр нормализует мат, транслит и литспик как раньше. После лимита предупреждений выдаётся мут. При сбое ИИ применяется локальный результат в рамках выбранного режима: в наблюдении санкций по-прежнему нет.

## Подключение ИИ (необязательно)

Переменные окружения:

- AI_CHAT_COMPLETIONS_URL — полный HTTPS URL метода chat completions вашего провайдера.
- AI_API_KEY — ключ API провайдера.
- AI_MODEL — идентификатор модели, поддерживающей messages и response_format=json_object.
- TEXT_RETENTION_DAYS — срок хранения текста подозрительных сообщений, цитат и контекста, по умолчанию 30, минимум 1 день.

Без всех трёх AI-переменных работают локальные правила; панель показывает, что ИИ не подключён. Для ИИ используется aiohttp, устанавливаемый с aiogram. Не кладите токены в исходники.

При настройке ИИ провайдеру отправляются текст сообщения, до шести предыдущих сообщений за последние десять минут (до 800 символов каждое), текст ответа и текущий счётчик предупреждений. Сначала проверьте допустимость такой передачи для своего чата и условия хранения у провайдера. Текст и контекст считаются недоверенными данными. Ожидание одного API-запроса ограничено 12 секундами, одновременно выполняются до четырёх запросов. При высокой нагрузке образуется очередь; нагрузочный тест с реальным провайдером не выполнялся.

Структура ответа: category, confidence (0..1), reason, evidence (точная цитата), action. Неверный JSON, ложная цитата, ошибка HTTP или таймаут возвращают локальный результат. У локальных правил нет выдуманного процента уверенности.

## Панель и история

«На проверке» открывает очередь, «История решений» — все решения с пагинацией. Из анализа открывается карточка участника. Поиск по ID или известному @username остаётся в разделе «Участники».

В карточке доступны предупреждение, мут, бан и снятие ограничения с подтверждением; статистика санкций с момента обновления, состояние Telegram, история решений, последние действия и статусы обжалований. Полная история обжалований доступна в исходной таблице appeals, последние пересмотры записываются в audit_log. В очереди обжалований сохраняется прежний интерфейс.

Когда появляется первая ожидающая проверка, у администраторов, которые запускали /start в ЛС, обновляется существующее сообщение панели. Если ЛС недоступны, решение остаётся в очереди. Администраторы проверяются заново при каждом действии; состояния ввода и сообщения панели разделены по Telegram ID администратора.

Подтверждение решения атомарно резервирует запись; два администратора не применят её дважды. Разовые ручные подтверждения также сохраняются в базе. При неопределённом результате Telegram или перезапуске во время санкции решение получает uncertain: повтор автоматически запрещён. Проверьте фактический статус в Telegram и выполните необходимое действие из карточки. Журнал хранит системное действие и отдельную запись с администратором для ручных действий/обжалований.

Текст, цитаты и контекст очищаются по сроку при просмотре истории, при анализе сообщений и раз в час. Оценка, категория, объяснение, версии правил/модели и результаты проверки остаются. Тексты прошедших проверку сообщений не сохраняются в базе. Последние сообщения для контекста находятся только в оперативной памяти и удаляются после десяти минут (служебная очистка раз в час). Резервные копии и данные у ИИ-провайдера имеют собственные сроки хранения.

Нужны права бота удалять сообщения, ограничивать и блокировать участников. Муты доступны в супергруппах. Администраторы, боты и сообщения от имени канала не модерируются. Бан и снятие бана доступны через карточку; существующие обжалования пока относятся к мутам.

## Проверка

python -m unittest discover -v

Автотесты выполняются без Telegram и ключа ИИ: старые сценарии, наблюдение без санкций, подтверждения, повторные решения, проверка прав, сбой ИИ, валидация ответа, миграции и очистка текста. Проверку с настоящим Bot API и выбранным ИИ-провайдером необходимо выполнить после настройки на хостинге. Бот на Bothost в рамках подготовки архива не запускался.
